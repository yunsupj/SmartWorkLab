Day 3에서는 각도 센서에 노이즈를 넣어도 PID 제어기가 +30° 목표를 따라갔다. 하지만 명령은 거칠어졌다. 센서 노이즈의 표준편차가 0.4°일 때, 연속된 토크 명령의 변화량을 RMS로 계산하면 **0.099 N·m에서 1.715 N·m**로 커졌다. 이번에는 간단한 필터로 명령을 부드럽게 만들면서 추적 성능도 지킬 수 있는지 확인했다.

노이즈만 넣은 실험에서는 어느 정도 효과가 있었다. 지수이동평균(EMA)의 alpha를 0.2로 두자 다섯 시드의 명령 변화 RMS 평균이 **0.245 N·m**로 내려갔다. 그런데 같은 필터를 측정값이 불규칙하게 도착하는 조건에 넣자 결과가 뒤집혔다. 다섯 실행 중 네 번은 시뮬레이터의 실제 관절 각도가 ±360°를 넘었고, 나머지 한 번도 10초 안에 안정되지 않았다. 실패한 궤적을 지우거나 게인을 바꾸지 않고, 제어기가 어느 시점에 무엇을 봤는지 추적했다.

여기서 말하는 진자는 MuJoCo 안의 힌지 하나다. 실제 로봇 관절이나 하드웨어용 안전 제어기를 검증한 결과가 아니다.

## 먼저 고정한 조건

Day 2와 Day 3에서 쓴 모델과 PID를 그대로 유지했다. 진자의 질량은 1 kg, 길이는 0.5 m, 중력은 −9.81 m/s²이다. 물리 계산은 RK4로 2 ms마다 진행하고 제어기는 10 ms마다 새 토크를 결정한다. 0.5초에 목표 각도를 0°에서 +30°로 바꾸고 10초 동안 기록했다. 토크 범위는 ±3 N·m, 게인은 **Kp=6, Ki=3, Kd=1**이다. 깨끗한 조건에서는 Day 3 결과가 그대로 나왔다. 마지막 2초간 평균 절대 오차(MAE)는 **0.313°**, 목표가 바뀐 뒤 안정되는 데 걸린 시간은 **3.630초**였다.

추적 성능은 필터 출력이 아니라 MuJoCo의 실제 관절 각도 `qpos`로 계산한다. 마지막 2초간 MAE는 8–10초 구간의 평균 절대 오차이고, 스텝 이후 RMSE는 0.5–10초 전체를 본다. 안정됐다는 것은 그 시점 이후 모든 물리 샘플이 목표의 ±2° 안에 머물렀다는 뜻이다. 명령 변화 RMS는 10 ms 간격으로 내린 두 토크 명령의 차이를 N·m 단위로 계산한다. 명령이 부드럽다는 사실만으로 진자도 잘 따라간다고 말할 수는 없다.

확률이 들어가는 실험에는 **11, 23, 37, 53, 71** 다섯 시드를 썼다. 아래 표의 값은 별도 표시가 없으면 다섯 실행의 평균이다. 시드별 수치와 관측 범위는 [원본 결과 JSON](https://github.com/yunsupj/mochi-sprout/blob/fd02d251f1304ba92e37a0a95d6a8f77a344d57c/experiments/day04/summary.json)에 있다.

## 노이즈만 있을 때는 필터가 도움이 됐다

제어기 업데이트마다 평균 0, 표준편차 0.4°인 가우시안 각도 노이즈를 새로 뽑았다. EMA는 **채택된 측정값**이 들어올 때만 갱신한다. 아래 식은 [실제 구현](https://github.com/yunsupj/mochi-sprout/blob/fd02d251f1304ba92e37a0a95d6a8f77a344d57c/src/mochi_sprout/simulation/observation.py)에서 가져왔다.

```python
self.value = (value if self.value is None else
              self.alpha * value + (1 - self.alpha) * self.value)
```

첫 측정값으로 필터 상태를 시작하고, alpha가 1이면 받은 값을 그대로 쓴다. alpha가 작을수록 지난 값의 영향이 오래 남는다. 노이즈는 줄일 수 있지만 실제 각도가 변할 때 따라가는 속도도 늦어진다.

| 0.4° 센서 노이즈 | 마지막 2초간 MAE | 스텝 이후 RMSE | 명령 변화 RMS |
|---|---:|---:|---:|
| 필터 없음, alpha 1 | 0.390° | 4.396° | 1.715 N·m |
| EMA 0.8 | 0.319° | 4.323° | 1.242 N·m |
| EMA 0.2 | 0.296° | 4.126° | 0.245 N·m |
| EMA 0.1 | 0.289° | 4.450° | 0.150 N·m |

alpha 0.1은 이 다섯 시드에서 마지막 2초간 MAE가 가장 작고 명령도 가장 부드러웠다. 그러나 스텝 이후 전체 RMSE는 alpha 0.2보다 나빴다. 현재 실제 각도와 필터 출력의 차이를 RMS로 보면 2.050°였고, alpha 0.2에서는 0.695°였다. 필터가 노이즈뿐 아니라 실제 움직임도 늦게 따라간 것이다. 마지막 2초의 숫자 하나로 필터를 고르면 이 차이를 놓친다.

## 측정 시각과 도착 시각은 다르다

다음에는 측정값의 도착 시간을 바꿨다. 센서는 제어기 업데이트 시각마다 측정하지만, 각 메시지의 지연을 **10, 30, 50, 70, 90 ms** 중 하나로 뽑는다. 분포의 이론적 평균은 50 ms로 고정 50 ms 조건과 비교할 수 있다. 다섯 시드에서 실제로 뽑힌 지연의 평균은 **50.048 ms**였다.

메시지마다 측정한 시각과 도착할 시각을 따로 기록한다. 아직 도착하지 않은 측정값은 제어기에 보이지 않는다. 한 번에 여러 개가 도착하면 도착 시각, 그다음 생성 순서로 처리한다. 이미 채택한 값보다 더 오래된 측정은 뒤늦게 와도 버린다. [관측 파이프라인](https://github.com/yunsupj/mochi-sprout/blob/fd02d251f1304ba92e37a0a95d6a8f77a344d57c/src/mochi_sprout/simulation/observation.py)의 핵심 부분이다.

```python
while self.pending and self.pending[0][0] <= decision_time_s + 1e-12:
    arrival_time, _, measurement_time, value = heappop(self.pending)
    if self.has_measurement and measurement_time <= self.latest_time_s:
        dropped += 1
        out_of_order += 1
        continue
```

첫 센서 값이 오기 전에는 초기 각도 0°를 알고 있다는 가정을 명시적으로 표시해 사용한다. 실제 시간에 `sleep`을 걸어 지연을 흉내 내지 않았고, 미래의 측정값도 읽지 않았다.

노이즈와 필터 없이 지연만 불규칙하게 만든 다섯 실행은 모두 안정됐다. 스텝 이후 RMSE 평균은 4.463°였다. 고정 50 ms 한 번의 결과는 4.177°였다. 둘은 명목상 평균 지연이 같아도 같은 조건이 아니다. 오래된 값의 도착 순서와 폐기 규칙이 제어기에 남는 정보의 나이를 바꾼다.

## 필터와 가변 지연을 합치자 다른 결과가 나왔다

0.4° 노이즈와 가변 지연을 넣되 **EMA 없이** 돌린 다섯 실행은 모두 안정됐다. 같은 조건에 EMA 0.2만 더하자 마지막 2초간 MAE 평균이 **241.722°**로 올라갔다. 다섯 시드의 관측 범위는 **197.658–290.467°**다. 네 번은 실제 관절 각도가 ±360°를 넘었고, 남은 한 번은 각도가 유한했지만 안정되지 않았다. MuJoCo 힌지에는 각도 제한이 없다. 그래프의 각도가 한 바퀴를 넘어가는 것은 표시 오류나 단위 변환 문제가 아니라 실제 시뮬레이션 상태다.

![시드 11의 기준선, 노이즈와 가변 지연, 같은 조건에 EMA 0.2를 더한 실제 각도](/images/lab/mochi-sprout-day04-combined-tracking.png)

*그림 5. 시드 11의 실제 각도. 필터를 넣은 실행은 ±360°를 넘고, 필터 없는 실행은 안정된다. 하드웨어에서 관측한 현상이 아니다.*

먼저 메시지 큐를 확인했다. 각 가변 지연 실행에서 측정은 **1,000개** 생성됐다. 마지막 제어기 결정 시각인 9.99초까지 **995개**가 도착했고, 다섯 개는 아직 대기 중이었다. 시드에 따라 도착한 메시지 중 **542–570개**가 이미 채택된 값보다 오래돼 버려졌다. 평균은 **550.8개**, 즉 **도착한 995개의 55.36%**다. 1,000번의 제어기 업데이트를 분모로 쓴 비율이 아니다. 독립적으로 도착 순서를 다시 계산해도 채택·폐기 수가 일치했다. 타임스탬프나 스케줄링 결함은 발견하지 못했다.

채택된 측정값의 생성 시각 간격은 평균 **22–23 ms**, 길게는 **70–80 ms**였다. 하지만 PID 제어기는 계속 **10 ms마다** 계산한다. EMA 0.2는 새로 채택한 측정이 있어야 움직인다. [PID 코드](https://github.com/yunsupj/mochi-sprout/blob/fd02d251f1304ba92e37a0a95d6a8f77a344d57c/src/mochi_sprout/control/pid.py)의 미분 항은 제어기 업데이트 간격을 쓴다.

```python
derivative = (
    0.0 if self.previous_measurement is None
    else -(measurement - self.previous_measurement) / dt
)
```

새 측정이 없는 시각에는 필터 출력도 그대로라 미분 항이 0이 될 수 있다. 반대로 새 측정이 채택되면 필터 값이 한 번에 움직여, 그 변화가 10 ms 한 번의 미분 항으로 들어간다.

## 궤적이 처음 어긋난 순간

실패를 마지막 숫자로만 설명하지 않으려고 시작점을 정했다. 목표가 바뀐 뒤, **필터를 넣은 실행의 실제 각도가 같은 시드의 필터 없는 실행보다 처음으로 5° 이상 달라진 물리 샘플**을 찾았다. 시드 11에서는 **0.686초**, 시드 23에서는 **0.684초**였다. 두 실행은 각각 같은 지연 추첨 결과와 센서 노이즈 잔차를 썼다.

시드 11의 **0.690초**에는 실제 각도가 **28.04°**였고 **3.23 rad/s**로 계속 올라가고 있었다. 마지막으로 채택한 측정은 0.660초에 생성됐지만, EMA 출력은 **11.89°**에 머물렀다. 그 제어기 업데이트에서는 새 측정값을 채택하지 않았다. P 항은 **+1.896 N·m**, 적분 후보 항은 **+0.156 N·m**, D 항은 **0**, 적용한 토크는 **+2.052 N·m**였다. 가까운 0.740초에는 새 값이 들어오면서 미분 항이 **−5.681 N·m**가 됐고 토크 명령은 **−3 N·m**로 제한됐다. [진단 CSV](https://github.com/yunsupj/mochi-sprout/blob/fd02d251f1304ba92e37a0a95d6a8f77a344d57c/experiments/day04/diagnostic_onsets.csv)에 시드 11과 23의 주변 기록이 있다. 시작점에서 적분 항은 P와 D 변화보다 작았다. 이번 실패의 주된 원인이라고 주장할 근거가 없다.

원인을 더 좁히기 위해 다섯 시드로 세 조건을 추가했다.

| 비교 조건 | 다섯 시드 결과 |
|---|---|
| 가변 지연 + EMA 0.2, **노이즈 없음** | 다섯 번 모두 ±360° 초과 |
| 0.4° 노이즈 + **고정** 50 ms + EMA 0.2 | 다섯 번 모두 유한했지만 안정되지 않음 |
| 노이즈 + 가변 지연 + EMA 0.8 | 다섯 번 모두 안정 |
| 기존 노이즈 + 가변 지연, **EMA 없음** | 다섯 번 모두 안정 |

이 모델과 게인에서는 필터가 과거 측정값을 오래 붙잡는 성질과 불규칙한 채택 시각이 함께 문제를 만든다는 해석이 가장 잘 맞는다. EMA가 일반적으로 위험하다는 뜻은 아니다. 실패를 없애려고 PID 게인을 다시 조정하지도 않았고, 이 결과 뒤에 상태 추정기를 덧붙이지도 않았다. **실패한 필터·지연 조합은 하드웨어용으로 검증되지 않았다.**

## 모찌 새싹에 남는 과제

관측 파이프라인은 MuJoCo에 의존하지 않는다. 측정한 때, 도착한 때, 제어기가 판단한 때를 분리하고 실제 물리 상태와 제어기가 본 값을 따로 남긴다. 나중에 교체 가능한 팔다리마다 센서와 지연이 달라지더라도 이런 경계가 필요할 것이다. 그렇다고 지금의 진자가 완성된 휴머노이드 관절인 것은 아니다.

[Day 4 연구 커밋](https://github.com/yunsupj/mochi-sprout/commit/fd02d251f1304ba92e37a0a95d6a8f77a344d57c)에서 다음 명령으로 실험과 진단을 다시 실행할 수 있다.

```sh
uv sync --locked --python 3.11
uv lock --check --python 3.11
uv run --locked --python 3.11 pytest -q
uv run --locked --python 3.11 python -m mochi_sprout.experiments.day04 --output-dir experiments/day04
uv run --locked --python 3.11 python -m mochi_sprout.experiments.day04_diagnostics --output-dir experiments/day04
```

병합된 코드의 전체 테스트는 **37개 통과**였다. [실험 기록](https://github.com/yunsupj/mochi-sprout/blob/fd02d251f1304ba92e37a0a95d6a8f77a344d57c/experiments/day04/README.md), [시드별 결과](https://github.com/yunsupj/mochi-sprout/blob/fd02d251f1304ba92e37a0a95d6a8f77a344d57c/experiments/day04/summary.json), [진단 자료](https://github.com/yunsupj/mochi-sprout/blob/fd02d251f1304ba92e37a0a95d6a8f77a344d57c/experiments/day04/diagnostics.json)에서 수치의 근거를 확인할 수 있다. 이 글의 그림 다섯 개는 [연구 저장소에 커밋된 PNG](https://github.com/yunsupj/mochi-sprout/tree/fd02d251f1304ba92e37a0a95d6a8f77a344d57c/experiments/day04)를 수정 없이 복사했다. 표지에는 병합 커밋의 통합 결과 그림을 썼다.

결론을 넓혀 말할 수는 없다. 실험 대상은 단순화한 진자 하나이고, +30° 스텝 한 번과 10초 구간, 확률 시드 다섯 개, 가변 지연 분포 하나, 고정된 게인만 시험했다. 모터의 전기적 동역학이나 접촉은 모델링하지 않았다. 실제 로봇 시험도, sim-to-real 검증도, 안전한 하드웨어 제어기 검증도 없다. 다음에는 타임스탬프를 반영한 필터나 예측 시간을 제한한 속도 추정을 별도의 작은 실험으로 검토할 수 있다. 아직 구현한 것은 아니다.
